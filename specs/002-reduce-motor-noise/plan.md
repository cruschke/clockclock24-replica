# Implementation Plan: Reduce Motor Noise During Synchronized Animation

**Input**: Feature specification from `/specs/002-reduce-motor-noise/spec.md`

## Summary

Reduce audible motor noise during clock animation—especially when all 24 hands move simultaneously—by implementing short startup staggering across the 8 PCB boards and globally reducing motor speed/acceleration. The combined approach uses source-level tuning (stagger interval 10-20ms default, speed 90%, acceleration 80% default) on the ESP8266 master controller to spread peak current spikes and reduce mechanical vibration, keeping all animations imperceptibly within ±200ms of baseline timing and visually indistinguishable from baseline quality.

## Technical Context

**Language/Version**: C++ (Arduino framework), PlatformIO, targeting ESP8266 (Arduino 3.1.2)  
**Primary Dependencies**: AccelStepper library, ESP8266 WiFi/WebServer core, TimeLib, Preferences, Wire (I2C)  
**Storage**: EEPROM via Preferences library (already used for timezone and config)  
**Testing**: Hardware validation on real Wemos D1 mini lite + 8 PCB boards with Raspberry Pi Pico slaves  
**Target Platform**: ESP8266 (master) controlling 8 Raspberry Pi Pico boards (slaves) via I2C  
**Project Type**: Embedded firmware (C++) + web UI (HTML/JavaScript)  
**Performance Goals**: 
- Noise reduction: ≥40% measured dB reduction during full-clock animation
- Animation completion: all 24 hands finish within 0 to +200ms vs baseline
- Visual quality: zero perceptible degradation at normal viewing distance
**Constraints**: 
- ESP8266 has ~80KB usable RAM, ~950KB usable Flash
- I2C communication to 8 boards with variable latency
- Loop timing for motor control must not be delayed beyond 10ms frame budget
**Scale/Scope**: 24 stepper motors across 8 boards; 3 animation modes (Lazy, Fun, Waves); minute transitions and full animations
